# ADR-001: Background Job System Choice

## Context

We need a background processing system for notifications (email, SMS, webhooks) with retry support.

## Requirements

- Asynchronous task execution
- Retry mechanism with backoff
- Simple operational setup
- Python-native integration

## Options Considered

### Celery + Redis

- Fast to implement
- Strong Python ecosystem support
- Moderate durability guarantees

### RabbitMQ

- Strong messaging guarantees
- More operational complexity

### Kafka

- High durability and replay
- Over-engineered for current needs

### AWS SQS

- Fully managed
- Cloud dependency and cost

## Decision

Celery with Redis/Valkey as broker.

## Rationale

- Prioritizes development speed and simplicity
- Matches current expected system scale
- Reduces infrastructure overhead

## Consequences

- Must design idempotent workers
- Requires Redis persistence tuning
- Potential migration needed at higher scale
